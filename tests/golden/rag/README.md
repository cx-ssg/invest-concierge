# M1 检索评测集 · 标注规范（v1）

> 建立：2026-09-17 ｜ 依据：两份外部评审的一致要求
> （`docs/M1_INGEST_AUDIT.md` §五、§七）

## 为什么需要它

在此之前，"验收"用的是 **8+8 条手写查询**，存在三个结构性问题（均被外部评审指出并经实测确认）：

1. **样本量不足**（n=4/类）：0/4 的 95% 置信上界约 **75%**，无法证伪"通过"；
2. **缺最关键的一类**：原 A3 只考"域外查询"，而**真正会诱发幻觉的是「域内无答案」**
   （问题里全是域内词、语料里根本没有那个事实）；
3. **出题偏置**：TUNING 组 3/4 条与文档标题字面覆盖率 ≥0.5（评审实测指出），
   BM25 侧"干净可分"有被构造的成分。

## 四类查询（`kind`）

| kind | 含义 | 期望行为 | 目标条数 |
|---|---|---|---|
| `in_domain_answerable` | 域内**可答**：答案确实在某块里 | 返回结果，**答案块命中 top-k**，不得判 `none` | ≥50 |
| `in_domain_unanswerable` | 域内**不可答**：词面在域内，但语料没有那个事实 | 不得进入生成上下文（`none` 或 `weak`） | ≥30 |
| `out_of_domain` | 域外：与本语料无关 | `none`（弃权） | ≥50 |
| `near_miss` | 近义干扰：词面命中但与问题所指不同 | `weak` 或 `none`。⚠️ 2026-09-19 更正：旧文案写「`weak`/`none`（**不得 `strong`**）」，而 `strong` 档已撤 ⇒ 该约束**恒真、无约束力**。**现行约束是「落 `weak` 时必须带 `WEAK_EVIDENCE_NOTE`」**（撤档后由代码保证：非 `none` 一律带警示语） | ≥30 |

## 标注格式（JSON）

```jsonc
{
  "id": "rel-0001",
  "kind": "in_domain_answerable",
  "query": "公司上半年营业收入同比变化如何",     // 必须**改写**，不得照抄标题
  "answer_chunk_ids": [12, 13],                 // 块级标注（store 的 chunks.id）
  "source_doc": "贵州茅台2026年半年度报告摘要",   // 便于人工复核
  "char_coverage_vs_title": 0.18,               // 与标题字面覆盖率（>0.5 视为有偏置，需重写）
  "note": "由 doc3 正文某段改写"
}
```

**不可答 / 域外 / 近义干扰**三类的 `answer_chunk_ids` 为 `[]`。

## TUNING / HOLDOUT 物理隔离（硬约束）

- **四个独立文件**：`queries_tuning_{rel,irr}.json`、`queries_holdout_{rel,irr}.json`
- **拟合阈值只读 TUNING**；**验收只读 HOLDOUT**
- 评测脚本在读取 TUNING 时必须**打印**：`本组已用于调参，不得作为验收依据`
- 出题时按 `id` 奇偶或哈希固定分流，**不得事后调整**（否则又变成自证）

### `batch` 字段与干净验收组（2026-09-17 引入）

v1 的负例在阈值调参时已被看过，其中 36 条却曾躺在 holdout 里当**验收**样本 —— 这是隐蔽污染。
现在用 `batch` 字段区分：

| 批次 | 含义 | 位置 |
|---|---|---|
| `v1`（无字段） | 首轮生成，**调参时已看过** | **负例**全部在 tuning；**正例**两组都有（holdout 的正例也是 v1） |
| `v2` | 二次重构新增，**从未参与调参** | tuning 20 条 + holdout 全部 |

- **holdout 的 50 条负例全部是 `v2`** → 干净验收组；
- ⚠️ **该约束有强制力**（2026-09-17 按独立审计 P2-2 补）：`scripts/rag_eval.py::assert_clean_holdout()`
  在跑 `--split holdout` 时校验，负例混入 v1 直接 `raise`。
  （此前 `batch` 字段**无人消费**，本节约束等于没有执行者。）
- 新增负例时**一律标 `batch: "v2"`**，且**不得用 tuning 里的 v2 样本**去定阈值（否则 holdout 又脏了）；
- 正例目前无 v2 版本（重标 gold 成本高），故 **holdout 的正例仍标 v1 性质** —— 报告时须说明。

### 分流按 kind 分层（修正"事后调整"禁令的例外）

v1 的两组 kind 构成不同（tuning 17/8/4 vs holdout 13/17/6），曲线不能外推。
v2 生成时**按 kind 分层奇偶交替分流**，保证两组构成一致 —— 这是**出题阶段**的分流，
不属于"事后调整"。**不得**为了凑指标把已定组的样本搬家。

## 指标（替代原来的"可分 / 不可分"）

| 指标 | 定义 | 说明 |
|---|---|---|
| `abstain_precision` | 判 `none` 的查询中，「本来就不该给」的比例 | 域外 + 域内不可答应判 none |
| `abstain_recall` | 应弃权的查询中，实际判 `none` 的比例 | |
| `over_abstain_rate` | 域内可答被判 `none` 的比例 | **闸门标注保守度**；⚠️ **不等于召回损失** —— `none` 档自 2026-09-17 起不再清空结果（此前它恰好是召回缺口的全部：`rel-0015` 的 gold 排 **rank 1** 仍被弃权） |
| **`delegated_rate`** | 负例**未判 `none`** 的比例（= 落 `weak`） | ⚠️ **撤档后语义已变**：落 `weak` **不再是"委派给判官"**（判官从未实现）⇒ 它是「**未通过判据、却带完整 `url`/`title` 返回给模型的结果占比**」= **暴露面**（第七轮审计二：更准的刻画是"**可被引用的错误断言**"的参数）。按 kind 分列看，不要只看总数 |
| `out_of_domain` 的 `none` 率 | 域外查询被**主动**判 `none` 的比例 | **A3a 主结论** |
| `Recall@k` | 答案块出现在 top-k 的比例 | 块级口径（`judge=None` 的**裸检索**）。答案**跨块时必须标全相邻块**，否则低估 |
| `tool_recall` | 同上，但走**工具真实形态**（`judge=judge` + 分层硬停） | ⚠️ **也是派生量**（= `Recall@k` − 被硬停吞掉的召回）。它**独有的价值在"路径"**：是唯一经过被测对象的检索指标。对照物是 `Recall@k`（**同义**），**不是** `trusted_recall`（后者额外要求 `level != none`） |
| `trusted_recall` | gold 在 top-k **且** `level != none` 的比例 | **判据采信过的召回**。⚠️ 2026-09-18 替换掉原 `guarded_recall` —— 两份外部审计**各自实测**证明后者**恒等于 `Recall@k`** |
| `MRR@10` | 首个答案块排名倒数的均值 | |

**报告方式**：扫 **none 档**阈值 → 输出 `(delegated_rate, over_abstain_rate)` 曲线 → 按代价选工作点 → **给区间**。
⚠️ 2026-09-19 **撤档后更正**：本行原写 `(strong_fp_rate, over_abstain_rate)`，而 `strong_fp_rate` **已随 `strong` 档移除**（分档只剩 none / weak）。
⚠️ 2026-10-01（F1）**再更正**：`scan()` 的 strong 曲线**已于该日彻底删除**（对象不存在），`--scan` 现输出 **none 稠密网格 + `SAR_NONE` 敏感性表**（v1 固定生产值 `V1_NONE`，6 行）—— 后者直接服务「要不要调高 `SAR_NONE`」的决策。
⚠️ 2026-09-17 起 headline 用 **`out_of_domain` 的主动弃权率**（当前 20/20 = 1.000）。
n<30 时不写"明显"这类词。
