# v1.3.1 —— 检索污染修复 + A3a/A3b 判据攻坚 + 历史回放引用 + 口径订正

> 本版是 **patch 版**：无破坏性变更，全部是对 v1.3.0 已有能力的问题修复、指标口径订正，以及一个前端补全。
> 详细审计过程与证据见仓内 `report-F-R1-evidence/`。

## 一、修掉的三个真实问题

### 1. 跨标的污染（`c12d3e1`）
v1.3.0 的语料只有茅台单一标的；扩到 4 个标的后，检索会把其它标的的公告混进结果
（实测：27 条茅台查询里 **23 条** top-5 被占据）。

**修法**：新增**查询侧标的识别**（`utils/rag/query_scope.py`）——识别到标的才收窄检索池，
**识别不到时保持全库**（跨标的/行业类查询不受影响）。返回体新增 `scope` 字段（`explicit|auto|full`）。

**效果**：同一查询形态下 **净效应 `Recall@5` 0.889 → 0.926**（污染 7/27 → **0/27**）。

### 2. A3a（域外弃权）退化（`c58f92b`）
语料扩大后 A3a 从 0.922 掉到 0.725。**根因经独立审计定位**：`v1` 的特征词相对带宽失衡
——用**零新内容对照**排除"库变大"这一解释（同样 20 篇原样复制 6 份 → 0/16 条翻转、A3a 不动）。

**修法**：`ρ` 由 0.05 收紧到 **0.02**（`feature_band()` 作为唯一实现）+ **弃权阈值重定标**。

**效果**：**A3a 0.725 → 0.863**。⚠️ 见下方限定第 2 条。

### 3. 判官候选窗不一致（`a1a003a`）
判官此前用 `retrieve_docs(top_n=5)`、而评测臂用 `max(k,10)` ⇒ 两个「top-5」来自**不同候选池**
（`kk=100` vs `200`），导致 3 条真正的漏判被误归因为"检索没召回到"。现已统一，并新增 `judge_fn_gold_recalled` 归因口径。

## 二、A3b（域内不可答）—— v1.3.0 时尚未做，本版首次推进

三条手段逐条做了对照实验：**抽取式作答**（要判官**证明**能回答，而非**声称**）**被采用**；
**要素覆盖**因**误杀同义改写**（`judge_fn` → 0.308）**被否决**；**实体边界检查**边际有效、因**唯一确定性**被保留。

| 判据（`docs/M1_EVAL_REPORT.md` L147 定义） | 门槛 | 实测 | 结论 |
|---|---|---|---|
| `judge_fp` | ≤0.10 | **0.097** | ✅ 达标 |
| `span_valid` | ≥0.95 | **0.951** | ⚠️ **中位数达标、区间跨越门槛** |
| `judge_fn` | ≤0.15 | **0.192** | ❌ 未达标 |

## 三、评测口径改进（`c79f2ca`）

`rag_eval.py` 新增 **`prod` 口径**（经 `retrieve_docs`/`query_scope`），**与既有 `full` 口径并列输出**（原口径未改动）。
两种口径含义已打印在输出里，避免误读。

## 四、前端：历史回放显示引用来源（`G1-2`）

v1.3.0 时**只有新产生的消息**带引用来源；**切回旧会话**时看不到。
本轮查清根因：**`sources` 从未落库** —— `agent_messages` 无对应列，且历史接口只回 `{role, content}`
（tool 行整行丢弃）。

**修法**：`agent_messages` 加 `meta` 列（JSON，**幂等迁移**），落 **`sources` + 判官结论**；
历史接口按「**没有就不出现该键**」透传（不破坏既有消费方）；前端**复用**新消息已有的来源卡组件。
**老会话不回填**（`meta = NULL` ⇒ 回放不显示来源区）。

**验证**：
- **真浏览器**点开历史会话 → **5 条来源**（标题 / 日期 / 链接）+ **每条带判官标注**（`判官：相关` / `判官：无关`），
  正文 `[n]` 引用标记正常
- 红断言 `scripts/verify_g1_replay_sources.py` **RED → GREEN**
- `pytest -q` → **616 passed**

## ⚠️ 五、读本版指标前必须知道的四条限定

1. **`prod` 口径是「oracle 上界」，不是产线实测** —— 该口径的 query 含**由金标派生的标的**信息。
   它代表"**已知标的**时"的能力上限；`full` 口径（全库）代表"**无法识别标的**时"的能力。
   **`query_scope` 的真实净贡献是 0.889 → 0.926**（不是 0.593 → 0.926，后者含"查询形态效应"）。
2. **A3a = 0.863 是被 holdout 二次标定过的拟合值**，**不能称"holdout 验收"**。
   引用时请带上：`holdout；阈值经 holdout 派生夹具臂二次标定；S=0.075 vs 0.08 差 1 条`，
   敏感性区间 **[0.863, 0.902]**。（0.902 实测可达，但需**第三次动用 holdout** ⇒ **主动不取**，宁可报保守值。）
3. **`full` 口径 0.593 / 0.386 是刻意保留的** —— 它代表"系统无法识别标的时"的真实能力，**不是"没修好"**。
4. **`judge_fn` 中「判官自身」的份额是上界口径下的值**（gold 落在候选窗内才计入分母）。
