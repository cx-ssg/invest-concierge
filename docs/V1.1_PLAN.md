## A. 价格预警（ROADMAP P3 兑现，习惯回路核心）

**机制**：用户设定触发条件 → 后台低频轮询 → 托盘气泡拉回访。桌面形态（托盘常驻）相对网页的最大优势场景。

**现状遗迹（直接复用）**：导航项 `alert`（live=false，nav_service.py:52）· `load/save_alert_settings()`（data/database.py:533）· 托盘 `notify()`（desktop/tray.py:68，pystray icon.notify 已封装）。

**设计**：

| 层 | 内容 |
|---|---|
| 存储 | 放弃 JSON 文件遗迹，新建 SQLite 表 `alerts`（id/symbol/name/kind[fund\|stock]/metric[estimate_pct\|price]/op[above\|below]/threshold/enabled/last_triggered_at/created_at）。JSON 老函数退役（gitignore 里的 alert_settings.json 同步清理）。**SQL 一律参数绑定**（项目安全约束，禁拼接/format 组装） |
| 触发器 | uvicorn 进程内 daemon 线程（FastAPI lifespan 启动），**仅交易时段（周一至五 9:30-15:00）+ 仅已启用的标的 + 10 分钟/标的间隔**——三重限频防东财风控；行情读取复用 fund_api/stock_api 现有 TTL 缓存，不新增直连 |
| 判定 | 基金=当日估值涨跌幅（gszzl）越限；股票=现价越限。**数据口径（评审补强①）**：触发判定用当时快照值，但基金盘中估值（gszzl）与收盘后真实净值常漂移 0.5-1%——通知文案必须标注「按盘中估值，非最终净值」，预期管理前置。触发后写 `alerts_events`（alert_id/message/created_at）+ 置 last_triggered_at，同一自然日内不重复触发 |
| 通知 | 三通道按可用性降级：① pywebview 壳=托盘 notify（真机实测项）；② 通用=应用内红点 + 顶栏角标（前端 30s 轮询 /api/alerts/events 未读数，复用 status 轮询连接习惯）；③ Electron 实验线后补 Notification API |
| 前端 | alert 页 live=true 激活：列表 CRUD（React Query mutations）+ 事件时间线；持仓页每行加"🔔 设预警"快捷入口 |

**验收**：① pytest 覆盖判定逻辑（越限/同日去重/非交易时段跳过）≥8 用例；② 真机实测：设一条必触发预警 → 托盘气泡出现 + 应用内角标 +1；③ 风控纪律：轮询请求全部走缓存路径（code review 断言无裸 requests）；④ 无 Key 全功能可用（预警不依赖 AI）。

## B. 持仓周报（例行价值，周五仪式）

**机制**：把"AI + 23 工具 + 个人持仓"组合成一键生成的内容，创造周五收盘后打开的理由。**v1.1 只做手动按钮**（周五自动生成存档放 v1.2，避免调度复杂化）。

**设计**：

- **入口**：资产总览页 PageHeader actions 加「生成周报」（PageHeader 组件已支持 actions 区）。
- **后端**：`POST /api/reports/weekly` → ① 纯数据层：list_funds() 全持仓本周涨跌（dwjz 对比成本净值/上周净值）、合计市值与盈亏；**大盘对比拆成两个独立数字（评审补强②）**：本周沪深300 涨跌（指数日线行情——实现时验证数据源：akshare 指数日线或 get_stock_kline 指数代码支持；不可得则该项降级为仅显示估值分位）+ 当前估值分位（get_index_valuation，注意它是 PE/PB 分位不是涨跌，两者不能混用）；② AI 层（有 Key）：把 ① 的聚合 JSON + 工具环开放（get_market_moneyflow/get_hot_sectors 相关性筛选）交给 agent_run 专用 prompt（禁编造：所有数字必须来自工具返回，复用防幻觉守则）；输出结构化 markdown。
- **降级**：无 Key = 纯数据卡（① 直接渲染，标注"配置 Key 可解锁 AI 点评"）。
- **落库**：新表 `reports`（kind/week/params/md_content/created_at），同周重复生成覆盖；前端侧滑面板渲染 markdown。

**验收**：① 生成 ≤60s（有 Key）/ ≤3s（降级）；② 输出数字抽查与手动计算一致（锚点：持仓 2 只样本）；③ 无 Key 降级卡可渲染；④ pytest ≥6 用例（聚合/覆盖写/空持仓边界）。

## C. 记忆显性化（性价比之王，感知到的智能才是粘性）

**现状**：memory 底座全在跑（agent_core.py:445 追问链重放最近 6 条 user/assistant、满 8 轮摘要、落库 agent_messages），但用户**完全感知不到**"它记得我"。

**设计**（三层，全部小改）：

1. **注入**：agent_run 开头（memory=True 时）把紧凑持仓快照并入 system 上下文——复用 P1 的 load_funds_snapshot（前 6 只、含 metrics，已容错），格式化为 ≤200 字「已知用户上下文」。回答因此天然会说"结合你的持仓…"。
2. **句式约定**：system prompt 追加一条——回答引用了用户持仓/历史对话时，自然地点出依据（如"你持仓里的 XX"）；**禁止编造记忆**，上下文为空就当没有。
3. **可见性**：SSE 新事件 `memory_used`（payload: `{"sources": ["holdings", "history"]}`），agent_core 在实际注入发生时 emit；ChatArea 时间线渲染**动态 chip（评审拍板④）**——按 sources 数组显示实际注入内容：仅持仓→「已结合你的持仓」、仅历史→「已结合历史对话」、两者→「已结合你的持仓 · 历史对话」。无注入不发事件（不撒谎）。
4. **隐私边界（评审补强③）**：持仓并入 system prompt 意味着每次对话都会把持仓数据发送给 DeepSeek——设置页加开关「允许 AI 读取我的持仓」（默认开、可关，存 settings）；关闭时不注入持仓、`memory_used` 不发 holdings 来源、回答不得暗示知道持仓（历史对话重放行为不变，那是聊天功能本体）。开源项目这个点必被用户问，设计期写明优于事后解释。

**验收**：① 有持仓时问"我现在该加仓吗" → 回答引用持仓事实 + chip 出现且内容与实际注入一致（动态）；② 空持仓新会话 → 无 chip、无编造；③ 演示模式不注入；④ **隐私开关关闭** → 不注入持仓、无 holdings 来源、回答不暗示知道持仓；⑤ pytest ≥6 用例（注入格式/空边界/事件触发条件/开关关闭路径）。
