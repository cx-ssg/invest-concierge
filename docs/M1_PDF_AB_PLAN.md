# M1 · 双轨语料对照实验（PDF 全文 vs API 正文）—— 实施计划

> 生成：2026-10-01 22:4x ｜ 用户拍板：**③ 折中（双轨语料，先量化再决定）**
> 前序实测（commit `1e4ae90`，`M1_EVAL_REPORT.md` §5）：东财 `notice_content` 在 ~5000 字截断；
> 同一篇半年报 **API 正文 3,040 字** vs **巨潮 PDF 全文 118,591 字 / 110 页**（含管理层讨论与分析完整章节 + 财务报表）

## 0. 一句话目标

**量化「把语料从 API 正文换成 PDF 全文」能多答对多少题** —— 用数字决定是否值得全面切换
（全面切换的代价是 98 条评测集 gold 重标 + 全指标重跑）。

## 1. 铁律：**双轨完全隔离**

| 不许动 | 理由 |
|---|---|
| `kb.db`（现有 75 块语料） | 它是 346 条测试与全部既有指标的基线 |
| `scripts/rag_ingest.py` | 现有采集路径（东财 API）保持可用，作为快路径 |
| `tests/golden/rag/`（98 条评测集） | 其 gold 是 chunk_id，跨语料不可对齐 |
| 现有测试 | `346 passed` 必须保持 |

新增物：`scripts/rag_ingest_pdf.py`（巨潮 PDF 采集）、`scripts/rag_pdf_ab.py`（对照评测）、
独立库 `kb_pdf.db`、`data/corpus/pdf/`（PDF 落盘）。

## 2. 为什么用「独立库」而不是「同库加 source」

`utils/rag/store.py::get_conn(path)` 支持任意库路径 ⇒ 隔离成本几乎为零；
同库方案会让现有 `load_index()` 立刻看到 PDF 块，**污染基线**且使既有指标不可比。

## 3. 对照评测怎么设计（本计划的核心）

跨语料 **chunk_id 不可对齐** ⇒ 不能用现有 gold 判召回。改为：

1. **问题集**：**只取「答案落在截断之后」的问题**（即 API 语料里**根本不存在**答案）——
   这是截断造成的真实损失面。来源：从半年报 PDF 的**财务报表 / 管理层讨论**章节取 10 个
   可判定的事实点（如「经营活动产生的现金流量净额」「基本每股收益」「合同负债期末余额」）。
2. **判定**：对每个问题，在**两个库**上跑同一条检索路径（`build_index` → `hybrid.run_hybrid`），
   检查 top-5 里是否出现**该答案的数字串**（数字做**归一化**：去千分位、`元` 等）——
   `hit@5(api)` vs `hit@5(pdf)`。
3. **预期**：`hit@5(api) ≈ 0/10`（答案不在语料里），`hit@5(pdf) ≥ 8/10`。
   若 API 侧 >0 ⇒ 说明我造的问题点选错了（答案其实在前 5000 字）→ 重选，不是"补全文没用"。
4. 另报 `judge` 的档位（`none`/`weak`）分布，看闸门在两套语料上的行为差异。

⚠️ **纪律**：问题集**在跑之前**先落盘（防事后挑选）。若发现某题答案其实在 API 语料内，**标注并保留**（不删）。

## 4. 步骤（TDD；每步含验收命令 + 预期）

### Step 1 纯逻辑单测（RED → GREEN）
`tests/test_pdf_ingest.py`：
- 巨潮响应解析：给定**固定 JSON fixture** → 抽出 `(title, adjunctUrl, date)`；
  过滤"摘要"条目；`adjunctUrl` → 绝对 URL

**验收**：`python -m pytest -p no:warnings -q tests/test_pdf_ingest.py` → 全绿（且新增不破坏 346）

- 巨潮列表（POST `hisAnnouncement/query`）→ 下 PDF（`static.cninfo.com.cn`）→ `pypdf` 抽取

**验收**：
```
python scripts/rag_ingest_pdf.py --code 600519 --limit 2 --db kb_pdf.db
```
→ 退出 0；打印「下载 N 篇 / 抽取字符数 / 块数 / embed 块数」；
`python -c "..."` 查 `kb_pdf.db` 的 `stats()` → 块数 > 300（对照 kb.db 的 75）

### Step 3 对照评测 `scripts/rag_pdf_ab.py`
- 内置**预注册**的 10 条问题（含预期数字）

→ 打印 10 行对照（含 `api_hit` / `pdf_hit` / `api_level` / `pdf_level`）+ 汇总行

### Step 4 回归 + 落盘
- `python -m pytest -p no:warnings -q` → **仍 346 passed**（双轨不污染）
- 把结论写进 `docs/M1_EVAL_REPORT.md` §5（下一轮）与黑板

## 7. 实测结果（2026-10-01 当晚跑完）

**语料规模**：半年报（`600519` 2026H1）API 正文 **3,040 字 / 5 块**（在 `kb.db` 的 20 篇 75 块之内）
vs PDF 全文 **118,591 字 / 198 块**（独立库 `kb_pdf.db`，向量化完成 198/198）。

**对照评测**（预注册 10 条**报表细节级**问题；判定 = top-k 块的数字集合是否含答案数字）：

| 语料 | hit@5 | hit@10 | 被弃权(none) |
|---|---|---|---|
| **API 正文（5000 字截断）** | **0/10** | **0/10** | 2/10 |
| **PDF 全文** | **8/10** | **10/10** | 0/10 |

- **自检**：0/10 条的答案出现在 API 语料里 ✅（问题集确实落在截断区之外）
- **阴性对照**：假答案 `9876543210.12` → **0/10** ✅（判定机制不虚高）
- PDF 侧 `hit@5=8/10` vs `hit@10=10/10` ⇒ 那 2 条只是**排序深度**（答案在 6–10 名），不是检索不到；
  API 侧**无论 k 多大都是 0** ⇒ 答案**根本不在语料里**。

**⚠️ 一条反向发现（决定结论的适用范围）**：**摘要级指标**（营业收入 / 归母净利润 / 基本每股收益 /
加权平均 ROE / 总资产 / 归母净资产）**API 语料里就有** —— 它们恰好落在前 5000 字内。
我最初自动筛的 13 条候选里有 **9 条**属于此类；**若拿它们做对照，会得出「补全文没用」的错误结论**。
⇒ **截断的真实损失面 =「报表细节（资产负债表/利润表/现金流量表明细）+ 管理层讨论正文」，
不是「摘要级指标」**。

**结论**：对报表细节级问题，补 PDF 全文把可答数 **从 0/10 提到 8/10（k=5）/ 10/10（k=10）**。
是否全面切换（代价：98 条评测集 gold 重标 + 全指标重跑）**待拍板**。

## 8. 明确不做（YAGNI）

- ❌ 不改主库、不改现有采集路径、不改评测集
- ❌ 不做表格结构化抽取（设计 §3.2 提到"表格单独抽为结构化块"）—— 本轮只验证"全文可得性"
- ❌ 不做 PDF 表格的版面还原（pdfplumber 的 `extract_tables`）—— 若结论支持切换再做

## 6. 回滚

新增文件删除即可；`kb_pdf.db` / `data/corpus/pdf/` 直接删除，主库不受影响。
