## 4. 结论（本轮最重要的判断）

**不能为提高 none 门槛去压 `weak_fp`** —— 代价是相关查询被成片误弃权
（`sar<0.15` 时 83%，`sar<0.20` 时 **100%**）。

**根因**：**域内不可答**查询（如「贵州茅台在人工智能领域的布局」）的字面特征与
**相关查询高度重叠** —— 都含域内实体词。`SAR`/`V1` 这类**字面判据在结构上无法区分它们**。
这与外部评审的独立实测一致（评审原话："域内无答案：**每个判据都被打穿**"）。

**处置**：
1. **A3a（域外弃权）已达成** —— `strong_fp=2.8%`；
2. **A3b（域内不可答）必须走 LLM 判官**，`weak` 档即其入口；**不应**靠调 `SAR_NONE` 达成；
3. **当前阈值保持不变**（`SAR_NONE=0.06 / V1_NONE=0.35`）—— 它是 `over_abstain=0` 的唯一工作点；
4. `weak` 档在 `retrieve_docs` 中已带明确指令文本（要求模型核验 / 如实说没有）。

> 换句话说：**检索层已经做到它能做的极限**（该拒的域外拒了、该给的没漏），
> 剩下的"域内无答案"是**语义判断问题**，必须交给 LLM —— 这正是"零成本替代 rerank"的落点。

## 4b. 第二轮外部评审对账（2026-09-17）—— 修正 §2 / §4 的三处表述

两份独立评审**各自复现了本报告的全部数字**（扫描表逐格一致），并指出三处需要修正。
以下每条都经我实测复核。

### ① 指标口径：`weak_fp` 与标注规范自相矛盾（**已修**）

`tests/golden/rag/README.md` 自己写的期望是「三类负例**都允许** `weak`，只有 `strong` 禁止」，
但 `weak_fp_rate` 把 `weak` 全算成 FP —— **在压一个规范并不要求压的量**。

**修正**（`scripts/rag_eval.py`）：`weak_fp_rate` → **`delegated_rate`**（委派率 = 成本指标，**不是失败**）；
`strong_fp_rate` **按 kind 分列**输出。

### ② `strong_fp` 混池把 A3a 算错了（**已修**）

| kind | n | none | weak | strong |
|---|---|---|---|---|
| `out_of_domain` | 6 | **6** | 0 | **0** ← A3a 实际**完美** |
| `in_domain_unanswerable` | 13 | 7 | 6 | 0 |
| `near_miss` | 17 | 3 | 13 | **1** ← 唯一违规 |

→ A3a 是 **0/6**，不是混池后的 2.8%；唯一的 strong 违规在 `near_miss`。
⚠️ 但 **n=6 太小**（0/6 的 95% 置信上界约 50%）→ **A3a 样本必须扩到 ≥50 才敢称达成**。

### ③ §4 的根因表述不准确（**已修**）

原表述「三类负例字面全重叠 → 无法区分」过于笼统。按 kind 实测应为：

| 负例类别 | 字面判据 | 实测 |
|---|---|---|
| `out_of_domain` | ✅ **完全够用** | 0/6 误放行 |
| `in_domain_unanswerable` | 🟡 可用字面换，但代价不实用 | over_abstain 0.23 → 0.46 |
| `near_miss` | ❌ **结构上不可判** | 无任何工作点 |

**打不穿的只有 `near_miss`** —— 它的词面**全是合法域内词汇**（战略 df=9、治理 df=8…），
缺的不是词而是**言语行为**（比较/排名/预测/评判），公告体例不产生这类句子。

另一份评审补充了更精确的机制：**两类样本按构造互相对立** ——
正例是 LLM **改写**（字面低），负例是规则**拼装**（字面高），
于是「字面重合高」在两类里是**反向**的 → 任何字面统计量都被结构性卡死。

**并且**：两位评审各自实测了 4~6 种替代字面判据（IDF 覆盖率 / 块内覆盖率 `cov_local` /
最长连续命中 `maxrun` / OOV 占比等），**全部打不过 SAR** → **字面判据这条路正式冻结**。

### ④ 三条**尚未修**的评测集质量问题（列入下一轮）

| # | 问题 | 实测证据 |

| 3 | **负例未分层 + 形状偏少** | TUNING/HOLDOUT 的 kind 构成不同（17/8/4 vs 13/17/6）→ 曲线不能外推；30 条域内负例只对应 **11 个形状**（n 的假象被高估） |

### ⑤ `V1` 的分词伪影（已确证，待修）

```
「每股能分到多少钱」→ 7 tokens，其中 6 个 df=0：股能 / 能分 / 分到 / 到多 / 多少 / 少钱
   → sar=0.0565, v1=0.000, level=none   ← 而答案就在语料里
```

全是**跨界 bigram**（词边界错位产生的伪 token）→ V1 被系统性压低，
是 **`strong` 档几乎不可达**（可答查询仅 1/21 判 strong）的主因。
修好它能把判官触发率从 86% 显著压下来（成本敏感项）。

### ⑥ LLM 判官：原型已实跑，但有**阻断性约束**

一份评审实跑了判官原型（qwen2.5:7b，判官看的是生成器会看的同 top-5 块）：
**闸门放行的 20 条负例，误放行 0/20** ✅ —— 干净解决了字面判据结构上做不到的事。

**但单次 43.7 秒**（90% 是 prefill：1530 prompt tokens → 25.7s）→
**本机 CPU 上"同步 inline 判官"不可交付**，必须走**异步/后台 + 流式**
（先返 `weak` + "核验中"，判完再更新）。

其提示词设计有三条实测教训（可直接采用）：判「材料是否足以回答」而非「有没有逐字写明」；
**让模型只输出 quote、块归属用确定性子串匹配推导**（id 字段不可靠）；
quote 需归一化后模糊匹配（`difflib` ≥0.75）。

### ⑦ 下一步顺序（两轮评审共识，按依赖排）

1. **修评测集**：正例加锚点门禁 + gold 错标审计 + 负例**按 kind 分层** + 扩 `out_of_domain` 到 ≥50
2. **修 `V1` 分词伪影**（让 `strong` 可达，压低判官触发率）
3. **加 `weak` 档指令文本**（`NO_HIT_MESSAGE` 扩展；先不上判官也能缓解）
4. **上 LLM 判官**（异步 + 仅 weak + 引文确定性校验），并**对判官本身出评测**
   （`judge_fp` ≤0.10 / `judge_fn` ≤0.15 / `span_valid` ≥0.95）—— **A3b 的判据落在这里，不在 `weak_fp`**
5. 字面判据**冻结在 SAR**，不再投入

### 🔴 P1-B｜`except TimeoutError` 在 Python 3.9/3.10 上抓不住看门狗超时（跨版本产线缺陷）

审计二在 **Python 3.10** 上实测 `test_tool_timeout_returns_timeout_error` **失败**
（本机是 3.11，故我一直没看见；`327 passed` 只在 ≥3.11 成立）：

```
E  AssertionError: assert 'TOOL_EXCEPTION' == 'TIMEOUT'
```

根因：`concurrent.futures.TimeoutError` 到 **3.11 才**成为内置 `TimeoutError` 的别名，
3.9/3.10 上是**另一个类** → `utils/agent_core.py` 的 `except TimeoutError:` 抓不住它 →
穿透到 `except Exception` → `error_code` 从 `TIMEOUT` 退化成 `TOOL_EXCEPTION`，
且 `_RETRYABLE_EXCEPTIONS` 判不上 → **`retryable=False`，「超时可重试」的语义整个失效**
（下游 `agent_run` / SSE / M1 检索正是按该字段分支）。而 CI 矩阵是 `["3.9", "3.11"]`、
README 宣称「Python 3.9+」。

**修法**：`from concurrent.futures import TimeoutError as FutureTimeoutError` +
`except (TimeoutError, FutureTimeoutError):`。
**测试**：3.11 上两者同类，真实 futures 无法复现差别（monkeypatch `cf.TimeoutError` 也无效 ——
`_base.py` 用的是自身模块名）→ 用**假执行器 + 假类注入**复现 3.10 的类层次（RED → GREEN 已确认）。
