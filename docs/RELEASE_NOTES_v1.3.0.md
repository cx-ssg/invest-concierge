## §1 本版内容 · M2 长期记忆层（承接上游，原有说明保留）

一句话：**给 Agent 加一层「你是谁、你做过什么」的长期记忆** —— 与 M1 的文档语料**分库存储**，
写入走「候选 → 用户确认」（**AI 不自行写记忆**），召回可预览、可删除、可一键关闭。

```
用户对话 ──┬─► preference 偏好（小、固定）─────► 每次对话必注入
           ├─► fact 事实（持仓/成本/关注标的）─► 按当前问题涉及的标的召回
           └─► experience 经验（决策 + 事后结果）► 向量召回 top-3（无向量时按时间倒序并如实标注）

隐式抽取 ──► memories_pending 候选 ──用户确认──► memories 正式表 ──► 注入 prompt
（AI 不自行落库）                        └─用户拒绝─► 丢弃
```

| 能力 | 说明 |
|---|---|
| **三类记忆** | `preference` / `fact` / `experience` **分离存储、分离召回**；去重靠 `UNIQUE(kind, key)`（经验用内容指纹作 key） |
| **写入时机** | 统一走「候选 → 用户确认」；显式「记住…」与手动新增同样可追溯（`source` 字段区分 explicit / implicit / seed） |
| **召回预览（审计入口）** | 设置页可模拟提问，直接看到「AI 到底会看到哪些记忆」的**原文**（所见即真实注入内容） |
| **隐私开关** | 「允许 AI 使用长期记忆」默认开；关闭后**不注入、不发事件、不暗示记得** |
| **注入契约** | 命中才注入 `## 长期记忆` 段 + 发 `memory_used` 事件（`sources` 细分为 `preferences` / `facts` / `experiences`）；**无命中不发事件**（不假装记得） |
| **API** | `GET/POST /api/memory`、`DELETE /api/memory/{id}`、`GET/POST /api/memory/pending`、`POST /api/memory/pending/{id}`、`POST /api/memory/summarize`、`GET/POST /api/memory/settings`、`GET /api/memory/recall-preview` |
| **设置页入口** | 「长期记忆」区：三类分组列表 / 单条删除 / 候选确认 / 手动新增 / 召回预览（**见 §2，已在本版落地**） |

> ⚠️ 口径说明：`CHANGELOG.md` 的 `[Unreleased]` 段仍写着「本版未做前端设置页入口」——
> 该句已被**同版本线内的 `feat(A1)` 提交（`331d172`）取代**（设置页长期记忆 UI 已落地）。

## §4 两个阻断级 BUG 的修复（本版重要卖点）

两个 bug 都**用户可见**、都**穿过了 5 层验证**（pytest / `tsc -b`+build / SSR 断言 /
真实 api 打真实后端 / 单页渲染截图），**只有真实浏览器端到端才暴露**。

| bug | 现象 | 根因 | 怎么发现的 |
|---|---|---|---|
| **BUG-001** | 新会话第一条消息的**回答完全不显示**（用户气泡在、后端约 7s 返回完整回答、无报错） | 可见性门控写了 `runVisible = phase.sessionId === activeId`，而 `done` 事件把 `phase.sessionId` 覆写成**新会话 id**，`activeId` 仍是 `null` ⇒ 回答落地瞬间视图被卸载 | **真实浏览器走完整问答**（上游实跑） |
| **BUG-002** | 新会话**第二条消息另起一个会话 + 上一条回答消失** | `onDone` 从不回写 `activeId`（实测会话分裂成 `[901, 902]`）；修复需**两行**，**只加一行经变异体实证会复发 BUG-001** | claude 审计（读码派）独有（上游记录） |

### 怎么保证不再犯（本版新机制）

1. **前端离线 DOM 回归网**：新增 `frontend/harness/`（jsdom）+ `scripts/verify_a2_dom.mjs`（**29 条断言**）。
2. **CI 变异自检**：`.github/workflows/ci.yml` 新增 `frontend-dom` job，除跑常规断体外，
   还跑 **4 个变异体**并要求**全部被抓住（CAUGHT）**：
   `--mutate bug001` / `--mutate bug002` / `--mutate bug002-partial` / `--mutate judge-uncertain-as-relevant`
   —— 防「harness 空转」（断言明明失效却仍全绿）。

> ⚠️ **状态口径**：29 断言 / 0 失败为 **已验证（D2a 实跑）**；变异自检脚本与 CI job 存在为

## §5 B1 · LLM 判官（异步 + 仅 weak 触发 + 引文逐字校验）

| 能力 | 说明 |
|---|---|
| **判官内核** | `utils/rag/llm_judge.py`：输入裁剪（`per_chunk_chars=800`）+ **引文逐字校验**（判 `relevant` 必须附 **≥12 字逐字引文**，做 substring 校验；引文不存在 ⇒ 该条降级 `uncertain`）+ 诚实降级（无 LLM / 超时 / JSON 解析失败 / 模型乱答 ⇒ 一律 `uncertain`） |

## §6 C1 / C1b · 采集层翻页聚合 + 语料全量重采

### 6.1 根因（推翻了黑板旧结论）

东方财富公告正文 API **是分页的**（每页 5,000 字），而旧实现把 `page_index` 硬编码为 `1`
⇒ **大报告只采到第一页**（封面 / 重要提示），「管理层讨论与分析」正文永远进不了语料。
更糟的是旧实现**没有任何「这篇文章有多长」的记录** ⇒ 截断**完全静默**、无法被发现。

### 6.2 修法（C1，`92f0702`）

`scripts/rag_ingest.py`（**+167 / −17 行**，`--numstat` 口径）：
`page_index` 可变 + 翻页聚合 + **5 个终止条件**（达到上游自报 `page_size` / 整页重复 / 空页 /
`MAX_PAGES=60` / 中途失败降级保留已取页）+ **空页退避重试** + `prune_stale_chunks()`
（块数变少时删除高位旧块）+ `--art-code` / `--body-log`（JSONL 逐篇可观测）。
`tests/test_rag_ingest.py` 新增 **13 条**回归锁（C-R1 再补 8 条 ⇒ 共 **31 条**）。

### 6.3 效果（口径必须写清：哪一篇、什么状态）

| 项 | 修复前 | 修复后 | 口径 |
|---|---|---|---|
| 同篇半年报（`art_code=AN202608141827994408`） | **5 块 / 3,040 字** | **183 块 / 119,491 字** | **逐页清洗后**字符数（raw 拼接为 217,480 字，**两种口径不可混用**；≈39×） |
| 生产库总量 | **268 chunks** | **281 chunks / 175,604 字** | 20 docs 固定；chunks 为库内行数 |
| 会议资料 doc#16 | 7 块 | **32 块** | C1b 收益最大的一篇（+16,335 字） |
| 全量重采质量 | — | **20/20 篇成功；0 失败 / 0 降级 / 0 截断 / 0 未嵌入** | 20 篇终止原因全部为「达到返回字段 `page_size=N`」 |

> ⚠️ **状态口径**：上表全部为 **未验证（上游实跑）** —— 本文档整理者**未重跑**采集/重采
> （需要真实网络 + 本地 Ollama；且生产 `kb.db` 已是被重采后的状态）。

### 6.4 诚实标注：`Recall@5` 0.952 → 0.905 是**排序漂移**，不是「重采有害」

- 口径：**holdout 的 21 条正例**；**PRE = 重采前备份库（268 块）→ POST = 重采后生产库（281 块）**。
- **逐条归因**：丢掉 top-5 的**只有 1 条**（`rel-0026`，gold `chunk#54` 属 doc#16，rank **5 → 7**）。
- **不是丢数据**：holdout 全部 **22 个 gold 块在 POST 中全部存在、文本逐字未变**（0 被改写 / 0 被删除）。
- **反事实实验**（上游实跑，复刻评测器检索路径）：
  CF1 = POST 去掉 doc#16 新增 25 块 ⇒ rank 仍 **6**（单靠 doc#16 不成立）；
  CF2 = CF1 再把 doc#6 还原 ⇒ rank 回到 **5** ⇒ **两个原因各挤一位**（doc#16 5→6 + doc#6 6→7）。
- ⇒ **只可说「语料变了，指标就变」**；**不得**说「重采有害」，也**不得**说「MRR 提升」
  （`MRR@10` 0.605 → 0.620 只是若干条 rank 漂移的净效果；n=21，且 holdout 是**拟合集**，脚本横幅自述
  「已用于阈值选择，阈值结论不得作为泛化依据」）。
