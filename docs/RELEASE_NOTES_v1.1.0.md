## 二、私域知识层（M1）

### ✨ 文档检索 `retrieve_docs`（第 24 个工具）

| | 说明 |
|---|---|
| 能力 | 上市公司公告 / 研报 / 财报原文切块入库，回答时**返回原文片段 + 来源 + 日期** |
| 存储 | 本地 SQLite + `bge-m3` 向量（1024 维，本地 Ollama，可降级 OpenAI 兼容端点） |
| 检索 | 混合检索：BM25 + 向量 → RRF 融合 + 同文档限额 |
| **证据分档** | 相关度不足时**主动弃权**：「证据不足档 —— 引用前请自行核验」，而不是硬答 |
| 采集 | 巨潮公告 API / **PDF 全文抽取**（`pypdf`），脚本化可复现 |

> 设计取舍：投资场景里最坏的失败模式是**自信的幻觉**。所以这里的准则是 —— **宁可说「没找到」，也不编。**

### 📈 检索层实测数据

⚠️ **下表每一行是一个独立的「语料 × 配置」状态，请勿跨行比较或拼接**（早期版本的本说明把不同状态的数字混在一行，已修正）。

| # | 状态 | 语料 | 同文档限额 | `Recall@5` | `MRR@10` |
|---|---|---|---|---|---|
| ① | v1.0.0 基线 | 旧语料 75 块（API 正文） | 无 | **1.000**（21/21） | **0.702** |
| ② | 切换 PDF 全文（大文档） | 新语料 268 块 | 无 | 0.857 ↓ | 0.593 ↓ |
| ③ | **+ 同文档限额 `max_per_doc=2`（= 当前产线）** | 新语料 268 块 | 2 | **0.952** | 0.605 |
| ④ | + LLM 重排（**离线探针，未接入产线**） | 新语料 268 块 | 2 | 0.952 | **0.706 ~ 0.738** |

**必读的三条**：

1. **③ 相对 ① 仍未完全回到基线** —— 召回 `0.952 < 1.000`（差 1 条）、`MRR@10 0.605 < 0.702`。
   同文档限额把召回基本修回，但**排序质量并未修复**；修复它需要 ④（尚未上线）。
2. **④ 是离线探针，产线没有接入** —— `git grep -i rerank -- utils/ services/ frontend/src` **零命中**；**产线当前 `MRR@10 = 0.605`**。探针两次独立运行得 `0.706` / `0.738`（第三方复跑仅得 `0.738`，未复现下限），因此应读作**区间而非固定值**。
3. **评测集性质（重要披露）** —— holdout 的**负例**是干净验收组（`v2`，从未参与调参，由 `assert_clean_holdout()` 强制）；但 **holdout 的 21 条正例仍是 `v1`——阈值调参时已经看过**。`scripts/rag_eval.py` 自身会打印：

   > `[eval] holdout —— ⚠️ 已用于阈值选择（拟合集），其上的阈值结论不得作为泛化依据`

   并且 `max_per_doc=2` 正是 holdout 上的扫描值（`None` 18/21 · `1` 17/21 · **`2` 20/21** · `3` 19/21 · `4` 19/21）⇒ **`0.952` 含拟合成分，不应作为泛化承诺**。

**复现命令（严格照此，否则数字对不上）**：

```bash
# ① 需旧语料备份（kb.db.20261001.bak 不入库；全新克隆须自行重建旧语料）
python scripts/rag_eval.py --split holdout --db kb.db.20261001.bak
# ② 当前库 + 关限额（需 --k 10 才与逐格扫描表吻合）
python scripts/rag_rerank_probe.py --no-rerank --k 10 --max-per-doc 0 --split holdout
# ③ 当前库（产线默认 max_per_doc=2）
python scripts/rag_eval.py --split holdout
# ④ LLM 重排探针（会调模型）
python scripts/rag_rerank_probe.py --split holdout
```

- **切换 PDF 全文的收益**：报表细节级问题 `hit@5` **0/10 → 8/10**（`hit@10` = 10/10）；阴性对照 0/10。
  代价是块数 75 → 268 带来的排序指标下滑（见上表 ②）。
- **LLM 重排的代价**：每查询 +k 次模型调用（本机实测 21 题全流程 45~60s，≈**2~3s/题**；会受机器与网络影响），接入前需解决延迟与成本。

⚠️ **如实记录**：`A3a`（域外弃权）等指标**未全部达标**。至少包含：A3a 因样本量不足不能称"达成"、`abstain_recall = 0.480`、`MRR@10` 未回基线、rerank 未接产线、以及上面的 holdout 拟合性质。逐项证据见 [docs/M1_EVAL_REPORT.md](docs/M1_EVAL_REPORT.md)（含「5. 诚实边界」）。
